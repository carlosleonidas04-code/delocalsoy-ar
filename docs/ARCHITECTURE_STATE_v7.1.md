## Decisiones vigentes

| Área | Decisión |
|---|---|
| Monorepo | Turborepo + pnpm (Track A) |
| Base de datos | PostgreSQL + PostGIS, exclusiva del sistema (docker-compose) |
| ORM | Prisma; ids `cuid`; columnas `@map()` a snake_case; migraciones versionadas + `migrate deploy` no interactivo |
| Eventos | `events_raw` append-only con `hash` único → idempotencia; **única fuente de verdad**. `system.*` es territorio del sistema: la ingesta pública lo rechaza (403, H-01 cerrado en CORE-004 R3a) |
| API | Express + TypeScript ESM. Rutas vivas: `/api/auth/{register,login,me}`, `/api/health` (honesto R5), `/api/health/mode` (guard R8), `/api/territorios?bbox=`, `/api/nodos`, `/api/nodos/:key`, `/api/nodos/:key/{capas,categorias,features,reportes}`, `/api/nodos/:key/subnodos` (VIG-001, #171), `/api/nodos/:key/kpis` (VIG-003, #182), `/api/patrimonio/:activoId` (VIG-004, #173), `/api/activos` (R5b), `/api/activos/:id/estado` (R5b), `/api/oportunidades` + `/api/oportunidades/:id` + `/api/oportunidades/:id/estado` (NCAP-R6, #158), `/api/evidencias`, `/api/events` (anti-PII ADR-027) |
| Web | Vite + React; contrato `DataSource` (ADR-029): `SyntheticDataSource` \| `ApiDataSource` (ADR-030) elegido por `VITE_DATA_SOURCE`. **R5-UI (#109):** capa ciudadana de activos — formulario `ActivoForm` validado con `@delocalsoy/contracts` (mismo schema que el backend, sin duplicación), capa propia en el mapa (marcadores por estado), sesión login/registro con token SOLO en memoria, preview sintético honesto (en memoria, no persiste) + modo `api` real (POST/GET `/api/activos`); `desproyecta` (ADR-030) traduce el mini-mapa del formulario a lat/lng real |
| Auth | **Identidad por etapas implementada (ADR-031, CORE-004 R3):** usuarios + JWT HS256 15 min + roles `ciudadano\|moderador\|admin`; contraseñas scrypt y HMAC con node:crypto nativo (**cero dependencias nuevas**); guards `requireJwt`/`requireRole` fail-closed sin `JWT_SECRET`; alta pública solo crea ciudadanos (promoción = operación de sistema con API key R8); sesiones selladas en `events_raw` sin PII (Ley 25.326). **R5a endurecimiento (auditoría #99–#102):** login con costo scrypt constante (anti-enumeración por timing), rate limiting 429 por IP+hash(email) en register/login (Redis INCR/EXPIRE con fallback memoria; `RATE_LIMIT_MAX`/`RATE_LIMIT_WINDOW_SEG`), 5xx sin mensajes internos (detalle solo en stdout del servidor), `/me` con manejo de errores |
| Activos | **Dominio `activos` (R5b, #87):** escritura ciudadana verificada — POST `/api/activos` autenticado crea el activo en estado `propuesto` con `created_by_hash` = sha256(usuario_id) truncado (**pseudónimo irreversible, sin PII — Ley 25.326, ADR-027**); anti-PII compartido (`lib/anti-pii.ts`) sobre título/descripción ANTES de persistir (ADR-020 cond. 1); toda escritura se sella en `events_raw` (`activo.propuesto`, `activo.estado_cambiado`) con **rollback si el sello falla**; moderación PATCH `/:id/estado` en `moderador\|admin` (409 sin transición); GET público anónimo con `?bbox=` PostGIS (ST_Intersects sobre índice GiST) y filtros `?estado=`/`?nodo=`/`?tipo=`/`?subnodo=`/`?n1=`. **VIG-002 (NODO-VIG NVIG-R2 #169):** extensión multimodal del mismo dominio — tipos `local|prestador|experiencia|observacion`, `subnodo_key` validado contra `subnodos` (sin FK dura, patrón oportunidades), `lat/lng` opcionales (R15: punto solo con fuente, trigger NULL-safe), visibilidad ADR-036 (`public|generalized|restricted` — restricted excluido de toda lectura pública; custodia VIG-004), procedencia ADR-035 + consentimiento granular (Ley 25.326), `is_synthetic` + `hash` único (idempotencia de la ingesta curada), tabla `activos_clasificaciones` (taxonomía N1→N3: una primaria + secundarias, fuente por clasificación) y estado `archivado` (retira del catálogo vivo) |
| Oportunidades | **Dominio `oportunidades` (NODO-CAPITAL NCAP-R6, #158 — Bloque 9 Banco de Potencialidades):** registro ciudadano verificado de capacidades, recursos, demandas y vacíos del desarrollo local — POST `/api/oportunidades` autenticado crea la oportunidad en estado `detected` con `created_by_hash` = sha256(usuario_id) truncado (**pseudónimo irreversible, sin PII — Ley 25.326, ADR-027**) y `hash` único de idempotencia; **evidencia obligatoria** (criterio mínimo del Bloque 9: sin evidencia no hay oportunidad, solo una señal); actores nombrados exigen `consent_confirmed` (Ley 25.326); anti-PII sobre título/descripción/evidencia/actores/tags ANTES de persistir (ADR-020 cond. 1); SIN geometría propia — contexto territorial por `nodo_key` + `subnodo_key` provisional (NCAP-R2 #154, criterio estructural #149: no duplicar geometría); sellos `oportunidad.propuesta` / `oportunidad.estado_cambiado` en `events_raw` con **rollback si el sello falla**; moderación PATCH `/:id/estado` en `moderador\|admin` con **matriz de transiciones** del ciclo de vida detected → under_review → validated → prioritized → in_development → active → implemented (+ paused/discarded/archived; 400 salto inválido, 409 sin transición); GET público anónimo con filtros `?nodo=`/`?tipo=`/`?estado=`/`?subnodo=` — `discarded` nunca se publica |
| Subnodos | **Dominio `subnodos` (NODO-VIG VIG-001, #171 — épica #167):** jerarquía territorial de 3 niveles del nodo iglesia (Opción B ratificada R9 2026-10-13): `district` → `paraje` → `subparaje` (+ `locality` INDEC), self-relation `parent_key` → `subnodos.key`; parajes de alta cordillera como hijos directos del nodo (parent null, `zone='alta_cordillera'`). Punto `lat/lng` SOLO con fuente pública (BAHRA WFS `ign:bahra_paraje` cod_depto 70049 / centroide Georef) — null honesto (R15/ADR-036), nunca inventado. `boundary_status='provisional'`; `assignment_status` honesto (`dh_directive` | `nearest_district_provisional` | `unverified`); `external_id` = cod_ase BAHRA o id Georef. Lectura pública `GET /api/nodos/:key/subnodos` (filtros `?type=`/`?parent=`; `parent=none` = hijos directos); seed idempotente de los lotes 1+2 ratificados por la DH (52 entidades; lote 2 ratificado 2026-10-13: 3 de travesía por cercanía + 15 de alta cordillera como hijos directos del nodo) con sellos `subnodo.creado` en `events_raw` (hash `seed-subnodo-*`). SIN escritura ciudadana ni geometría propia (criterio estructural #149/#167) |
| Patrimonio | **Dominio `activos_patrimonio` (NODO-VIG VIG-004, NVIG-R6 #173 — épica #167):** ficha patrimonial 1:1 con `activos` (`activo_id` único, FK Cascade) para el patrimonio protegido del nodo — declaratoria (norma + fuente), estado de conservación, reglas de acceso con fuente y punto público de acceso (`lat/lng` floats SIN geometría propia, criterio #149/#167); campo `sensible` (Json) NUNCA público (ADR-036): se publica null honesto con `sensible_status` (`sin_relevamiento`, R15) y `sensible_nota` queda solo para gestores. Custodia PATCH `/api/patrimonio/:activoId` en `moderador\|admin`: upsert de la ficha + transición de visibilidad del activo (`public\|generalized\|restricted`, ADR-036) en la misma escritura, anti-PII sobre todo texto, sello `patrimonio.custodiado` en `events_raw` (sin PII, `custodio_hash` sha32) con **rollback si el sello falla**. El activo `restricted` publica igual la ficha (la declaratoria es registro público) SIN el punto propio del activo. Seed idempotente de 3 fichas verificadas (Yacimiento Angualasto —Decreto 2.154/2009—, Capilla de Achango —Ley 24.790—, Molino de Bella Vista —Ley 25.291—) con sellos `patrimonio.ingestado` en `events_raw` (hash `seedev-pat-*`) |
| Asincronía | **R4 completo (ADR-032):** publish fail-open de referencias al stream `events:raw` (POST /api/events y sellos de mode; cliente RESP mínimo sobre node:net — cero dependencias; Redis real en CI y docker-compose; health reporta `redis: ok\|down`) + worker idempotente `@delocalsoy/worker` (consumer group `core004-worker`, XAUTOCLAIM, proyección `event_projections` — R4b `6441ca8`) + **VIG-003 (#182):** segundo consumer group `vig003-kpi` sobre el mismo stream — el evento NO es el dato, es el disparador: re-computa el set honesto v1 de KPIs del nodo desde las tablas de dominio y lo materializa en `kpi_snapshots` (upsert idempotente por `nodo_key`+`kpi_key`, nunca incrementos). `events_raw` sigue como única fuente de verdad |
| Gobernanza | Toda afirmación requiere evidencia ejecutable anclada a SHA (R4/R15). Repo privado sin branch protection (decisión DH 2026-10-07): compuerta = disciplina + CI verde en cada PR |
| Ecosistema multi-agente | agent-vibe, Anthropic (ADR-022), Perplexity (ADR-023), Grok (ADR-025), Google AI Studio `agent-google` (ADR-033: cliente con preview visual, pull-only, sin force push, cambios vía rama `agent-google/*` + PR + CI) |
